# lat.md

Release notes generated by Changesets. Earlier releases and the public release
history are in [lat.md/changelog.md](lat.md/changelog.md).

## 0.13.11

### Patch Changes

- Make `lat search` faster after editing a large `lat.md/`. Updating the index used to split every Markdown file into passages again whenever any file changed, which took several seconds on big graphs even though only the edited passages were re-embedded. Lat now remembers a hash of each indexed file and re-splits only the files that changed; on a 270-file graph, the index update after a one-file edit dropped from about 4.3s to 0.4s. Existing indexes pick this up automatically: the first update after upgrading still processes every file once.

## 0.13.10

### Patch Changes

- Fix Pi and OpenCode `lat_search` reporting "No results found." when the search actually failed. The generated tools killed `lat search` after 30 seconds and discarded every error, so a first search on a large `lat.md/` — which has to build the index — was cut off and restarted from scratch on each attempt, and a rejected `LAT_LLM_KEY` looked like an empty result. Query tools now run without blocking the agent, can be cancelled, and report the CLI's own message when a command fails or times out. `lat_search` allows two minutes; if the index still cannot be built in that time, the error says to run `lat search` in a shell first.

  Rerun `lat init` after upgrading to regenerate `.pi/extensions/lat.ts` and `.opencode/plugins/lat.ts`.

## 0.13.9

### Patch Changes

- 0a3898b: `lat ui` with a non-loopback `--host` now explains when no vault Markdown is shareable (for example, an untracked `lat.md/` in a Git project) and how to fix it, instead of crashing with a misleading "No readable Markdown files" stack trace.
- Handle projects without Git in the experimental commit checks. When the commit-hooks experiment is enabled outside a Git repository, `lat init` now warns that Lat works best with Git and suggests running `git init` first. You can continue without Git and choose whether `lat check` is enforced through coding agent hooks when an agent finishes a turn; previously such projects silently lost all validation. If the project later gains a Git repository, `lat check` reminds you to rerun `lat init` and switch to the pre-commit hook. Setups without the experiment are unchanged.
- Updated dependencies
  - @lat.md/core@0.1.5

## 0.13.8

### Patch Changes

- 2ac1aea: Check only the source being read when verifying external-source configuration around each file read. Commands no longer re-run Git identity checks on every other local checkout for each external file, which made `lat check` several times slower with multiple local overrides, especially on network file systems.
- Updated dependencies [2ac1aea]
  - @lat.md/core@0.1.4

## 0.13.7

### Patch Changes

- Allow pre-commit validation to check the working tree with `lat.git-pre-commit.validation: working-tree` in the staged root document's frontmatter. This supports documentation linking to ignored checkouts and local-only files. Staged validation remains the default, and the review bypass never skips validation.

## 0.13.6

### Patch Changes

- 835aba1: Use repository-configured pre-commit hooks on Git 2.54 and newer, preserving existing hook scripts and managers. Migrate unchanged Lat-owned hooks automatically and retain the legacy installer for older Git versions.

## 0.13.5

### Patch Changes

- d04a8f2: Give document and search-preview table columns a minimum width so text stays readable when adjacent columns contain long content.
- 6c27475: Add `lat init --experimental` to choose experimental features per project. Setup explains each feature and saves choices in `lat.md/.cache/experiments.json`; ordinary init preserves them, and rerunning the experiment checklist lets you disable them.

  The opt-in commit-hooks experiment moves agent validation from end-of-turn callbacks to Git pre-commit checks of staged content. Completion-hook behavior remains the default. Custom hooks and hook managers are preserved with integration instructions.

  The hook supports partial commits, linked worktrees, and internal symlinks under aliased temporary directories. Configure `lat.git-pre-commit.exclude-projects` in the repository's root `lat.md/lat.md` frontmatter to exclude intentionally invalid fixture projects.

  Agent commits with substantial staged code churn stop for a review of Lat coverage. After reviewing, agents can retry with `LAT_BYPASS_COMMIT_HOOK=1` when no update is needed or the changes are already covered, including by newly staged documentation. The flag skips only the review reminder; staged validation and other Git hooks still run.

## 0.13.4

### Patch Changes

- 271595d: Add `--host <address>` to `lat ui` and `lat ui run`. Use `--host 0.0.0.0` to
  listen on all IPv4 interfaces; the default remains `127.0.0.1`.

  Network listeners use read-only sharing restricted to public vault Markdown and
  explicitly linked public files. Hidden, ignored, untracked, and unlinked project
  files remain private. Git diffs and change indicators remain available for shared
  Markdown. Editing, search, and section-command output are available only in the
  private loopback UI.
